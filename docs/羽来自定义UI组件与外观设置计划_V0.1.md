# 羽来自定义 UI 组件与外观设置计划 V0.1

日期：2026-09-17
状态：代码已实现；自动检查与本地开发者工具打开通过；开发环境 CloudBase 集合、索引与云函数已部署并验证，双真机验收待执行。

## 1. 方向与成功标准

产品名称使用「外观设置」，入口设在「我的」。对开发者建立可复用组件，对用户开放有限且可预览的外观选项。羽来的首要任务仍是组局，组队与计分继续作为可独立使用的工具。

当前实现：用户能够选择蓝、绿、橙配色、明暗模式、组件文字大小与圆角、照片或渐变 Hero、球局卡片和计分板风格，预览后保存；可配置首页 Hero、快捷工具、常用场馆和模块顺序，并可主动开启跨设备同步。首页“我的球局”和“找球局”复用与 Hero 同宽的共享卡片。离开页面、重新进入小程序后设置仍生效，恢复默认随时可用。外观变化不得影响报名、候补、创建球局、比分和参与历史。

不把个人外观设置用于更改其他参与者看到的页面。计分板主题只改变当前设备的显示，不改变比赛规则和计分数据。

## 4. 用户流程

我的 → 外观设置 → 修改选项 → 预览 → 保存 → 返回。

- 进入页面时载入已保存设置，编辑仅影响预览区。
- 点击保存后更新本机配置与当前界面，给出清晰成功反馈。
- 尚未保存时直接返回不写入设置；页面持续提示「保存后生效」。
- 恢复默认先更新草稿与预览，再点击保存提交；避免误触立即覆盖。
- 保存失败保留草稿，明确提示未保存并允许重试。
- 新用户、配置损坏、旧版本不兼容时采用默认外观，小程序仍正常启动。

## 5. 组件拆分

按实际重复程度逐步替换，避免一次性重写全部页面。

| 组件 | 职责 | 关键要求 |
| --- | --- | --- |
| ui-button | 主、次、危险按钮及加载/禁用状态 | 固定对齐规则；核对表单、分享、头像选择等原生能力；特殊按钮允许先保留原生实现 |
| user-avatar | 图片头像和昵称首字回退 | 固定正方形、圆形裁切、图片加载失败回退 |
| activity-card | 球局核心摘要和两种密度 | 只展示服务端结果；不自行计算权限、人数或报名状态 |
| empty-state | 无球局、无历史等空状态 | 文案、插图和操作入口可配置 |
| tool-card | 保留并接入主题 | 不改变现有工具链接与功能 |
| score-board | 临时计分展示和操作事件 | 规则与显示分离；不得在样式迁移时复制或改写计分算法 |

球局内计分与临时计分是否共用完整组件，需要先核对现有交互差异；可以只共享分数显示部分。不要为了复用改变权限模型。

## 6. 技术设计

建议新增以下职责边界，具体文件命名遵循仓库现有风格：

- config/appearance.ts：默认配置、允许的枚举、预设主题元数据。
- services/appearance.ts：读取、校验、保存、恢复与版本迁移。
- styles/tokens.wxss：背景、表面、正文、次要文字、主色、边框、圆角和间距等语义变量。
- pages/profile/appearance.*：设置、预览、保存入口。
- 页面统一的外观应用方法：启动恢复、页面显示时更新、导航与背景适配。

配置示例：

```json
{
  "schemaVersion": 1,
  "theme": "blue",
  "activityDensity": "comfortable",
  "scoreTheme": "default"
}
```

推荐本地存储键：yulai:appearance:v1。仅存偏好，不存昵称、名单、比分或云端权限信息。设备上的账号切换共享此设备偏好，需保持「仅在本机生效」的说明准确。

渲染层只读取合法枚举；缺失字段补默认值，非法字段忽略，未知更高版本安全回退且不主动覆盖原配置。存储读取/写入异常均需捕获。

主题使用统一的语义值，不逐页维护另一套颜色。组件样式隔离、变量继承和原生导航外观在技术验证阶段核实；不能假设全局按钮样式会自动作用到组件内部。状态颜色与品牌主色分开，取消、危险、成功状态不随主题失去含义。

设置保存后，现有 Tab 页在下次显示时应用最新值；新打开页面首次渲染使用已恢复配置。不得使用持续轮询更新主题。

未来云同步使用独立偏好数据，仅允许当前用户读取和修改；同步失败保留本机值。其账号归属、时间戳/版本冲突策略须在单独阶段设计。

## 7. 分阶段排期

估算口径：一位开发者的工作日，包含必要联调，不是承诺交付日期。不含微信审核等待和用户预约真机测试时间。

| 阶段 | 工作 | 产物 | 预估 |
| --- | --- | --- | --- |
| UI-0 范围与技术验证 | 页面样式清单、两套配色、设置页草图、隔离/继承/导航验证 | 冻结选项与覆盖清单 | 0.5–1 天 |
| UI-1 组件与主题基础 | 语义变量、按钮和头像、球局卡片、tool-card 适配 | 可复用组件与默认外观回归 | 2–3 天 |
| UI-2 外观设置闭环 | 入口、预览、草稿保存、本机恢复、异常回退 | 可操作的外观设置页 | 1–2 天 |
| UI-3 页面覆盖与计分板 | 全页面主题覆盖、两种卡片密度、计分板配色、导航一致性 | 完整候选体验版 | 1.5–2 天 |
| UI-4 验收与文档 | 自动检查、真机回归、问题修复、README 更新 | 验收记录与发布说明 | 1–2 天 |

合计约 6–10 个工作日。若要求首版加入完整深色模式，单独预留约 2–4 天做全页面及资源适配，最终以 UI-0 盘点为准。

每个阶段形成独立、可回退的变更，提交时只包含相应范围。发布、上传体验版和正式审核仍按项目现有流程执行。

## 8. 验收清单

### 外观与布局

- 蓝、绿两套主题下所有入口可读，按钮文字横向纵向居中。
- 头像不拉伸，长昵称和长场馆名不挤坏卡片；关键时间和报名状态可见。
- 分享按钮大小和靠右位置正确；组织者操作排列一致。
- 舒适/紧凑卡片不隐藏关键业务信息；触控区域不因紧凑模式变得难以点击。
- 已加载的 Tab 页切换后也应用最新外观，首次进入无明显默认主题闪烁。
- 普通正文对比度目标不低于 4.5:1；不能只靠颜色区分状态。

### 偏好与异常

- 保存后退出重进仍有效；取消编辑保持原值；恢复默认只恢复外观。
- 配置缺失、非法枚举、旧版本、未知版本和存储异常均不导致白屏。
- 本机无网络仍可修改和保存设置；不因修改配色调用业务云接口。

### 业务回归

- 创建、报名、退出、候补、组织者管理、分享及参与历史保持原有行为。
- 原生分享和头像选择可正常触发；加载状态不能重复提交。
- 临时计分的单/双打、撤回、重开按原逻辑工作。
- 球局计分的参与者权限与分数同步不受主题影响。

### 验证方式

- 对偏好校验/迁移/存储错误回退做必要的逻辑测试。
- 运行仓库现有格式、类型、构建和相关业务检查；不对简单样式编写镜像断言测试。
- 开发者工具检查页面完整性和包体变化。
- Android 与 iOS 各一台真机，覆盖小屏/长文本/较大系统字号；记录机型和微信版本。
- 真机未完成时标记为「代码完成，真机待验收」，不能宣称已完成真机验证。

## 9. 主要风险与处理

- 全局样式进入组件后失效：组件内部显式声明布局，不依赖原有全局居中规则。
- 固定颜色遗漏：建立页面清单并检查样式、图片、导航和弹窗，不只替换主色。
- 按钮封装影响原生能力：特殊按钮先独立核对能力和事件透传，再迁移。
- 双份计分实现偏离：先保留现有算法，只改变展示层。
- 功能范围扩大：首页拖拽、分享海报编辑、任意图片上传及云同步独立排期。

## 10. 后续方向

优先级依次为：完整深色模式 → 工具数量增长后的收藏与排序 → 首页可选模块 → 跨设备同步 → 分享卡片模板。

当用户确实需要时，再做配置驱动的模块组合。首页的「我的球局 → 找球局」作为核心连续区域保留，不因自由排序破坏找局路径。此阶段另行定义哪些模块可移动、隐藏和新增。

首个实施动作：执行 UI-0，产出两套配色与设置页草图，并验证一个按钮、一个球局卡片在主题切换和真机上的表现；通过后进入 UI-1。
