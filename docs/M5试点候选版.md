# 羽来 M5 试点候选版

## 目标

M5 将 M1–M4 整理为可验证、可恢复、能阻止错误发布的试点候选版。仓库自动校验与真实平台验收分开执行：`pnpm check` 保证代码和交付物完整，`pnpm release:check` 只有在人工门槛全部记录证据后才通过。

## 候选版基线

- CI 执行格式、静态检查、类型检查、测试、M1–M5 校验和构建。
- 所有业务集合保持 `ADMINONLY`，小程序只通过统一云函数访问数据。
- `pnpm backup:cloud` 逐集合导出 JSON，并生成备份清单。
- `pnpm restore:plan -- --time "YYYY-MM-DD HH:mm:ss"` 生成写入隔离集合的恢复计划。
- `release/m5-gates.json` 记录人工门槛、负责人、状态和证据。
- 试点场馆种子数据保留 `PENDING_VERIFICATION`，现场核验前不会被当作正式数据。

## 自动校验

```bash
pnpm check
pnpm build
```

M5 自动检查发布脚本、备份目录隔离、集合权限、云函数超时与密钥引用、试点场馆种子数据，以及发布门槛是否完整。

## 人工发布门槛

| 门槛 | 通过条件 | 建议证据 |
| --- | --- | --- |
| 微信平台 | 主体、服务类目、备案、管理员和生产 CloudBase 环境均确认 | 后台配置记录及核验日期 |
| 隐私 | 隐私保护指引与实际字段一致，学校可留空和清空 | 审核清单、体验版页面记录 |
| 场馆数据 | 名称、地址、入口、场地编号、开放时间和联系人现场确认 | 现场核验表及照片编号 |
| 真机冒烟 | 创建、公开浏览、报名、候补、退出、开局和可选计分至少在两台真机通过 | 设备型号、微信版本、结果 |
| 性能 | 开发环境接口达到排期目标，并发报名无超卖 | 压测报告与云日志时间段 |
| 备份恢复 | 完整备份成功，至少一个集合恢复到隔离集合并核对记录 | manifest、任务号和结果 |

完成一项后，在 `release/m5-gates.json` 中将状态改为 `PASSED`，并填写可追溯的 `evidence`。正式发布前运行：

```bash
pnpm release:check
```

任何门槛为 `PENDING`、`BLOCKED` 或缺少证据时，命令都会失败。

## 当前限制

微信订阅消息仍需在公众平台确认类目和模板 ID 后接入。通知的业务事实继续以站内消息和球局详情为准，用户拒绝订阅不能影响报名。

M5 不会把未经现场确认的场馆地址写成正式数据，也不会在开发环境覆盖原集合。
