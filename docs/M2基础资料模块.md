# 羽来 M2 基础资料与组局发布

## 完成范围

- `user.getMe`：读取当前用户资料与是否需要补充昵称。
- `user.updateMe`：修改昵称、学校和自评水平；学校允许留空及清空。
- `school.list`：读取启用的学校候选项。
- `venue.list`、`venue.get`：读取公开场馆、核验状态和已启用场地。
- 小程序首页、个人资料页、场馆列表和场馆详情页。
- 广东工业大学学校候选项，以及学校状态加名称索引。
- `activity.create`、`activity.update`：创建及编辑球局，发布请求支持幂等，编辑使用版本号防止静默覆盖。
- `activity.list`、`activity.get`：公开球局列表和通过ID打开详情；仅链接可见球局不进入公开列表。
- 小程序找球局、球局详情和创建编辑表单。
- `registration.join`：在事务中完成正式报名或候补，重复请求不重复占位。
- `registration.leave`：本人退出；截止前正式成员退出时自动递补首位候补，截止后不自动递补。
- 球局详情展示本人报名或候补状态、候补位次和服务端人数；组织者及正式成员可查看名单。
- 受限联系方式仅对组织者和正式成员开放；候补和外部用户不可见。

所有数据仍通过统一 `api` 云函数读取或修改，业务集合保持 `ADMINONLY`。客户端不能提交 `role`、`status` 等未开放字段。试点场馆继续显示“待核验”，场号、位置和其他缺失信息不使用推测值。

球局创建默认公开，人数默认12且限制为4至40，联系方式默认仅正式参与者可见，组队和计分默认关闭。学校资料不参与创建校验。关键时间、场馆、位置和容量变更写入审计日志；修改使用版本号检测并发冲突。

报名容量、正式成员数组和候补队列保存在球局文档中，并与报名记录及正式参与者权限记录在同一云数据库事务中更新。球局文档是容量与候补顺序的事务事实源，`activityId + userId` 唯一索引继续作为重复报名的数据库防线。报名、退出和递补均写入审计日志。

## 验收结果

2026年9月9日：

- CloudBase学校索引和广东工业大学候选项写入成功。
- 云端 `school.list` 返回广东工业大学。
- 云端 `venue.list` 返回广东工业大学大学城校区体育馆及 `PENDING_VERIFICATION` 状态。
- 云端 `venue.get` 返回场馆详情；未核验场地保持空列表。
- CloudBase球局幂等唯一索引创建成功；最终 `api` 云函数已部署，`activity.list` 云端调用成功，报名路由的微信身份鉴权生效。
- 微信开发者工具最终预览编译通过，当前开发包大小约49.9 KB。
- 7个测试文件共28个测试通过，包含学校清空持久化、输入白名单、球局规则、默认值、创建路径和100请求并发报名事务测试。
- 报名状态机覆盖100人连续抢位不超容量、重复报名不占位、截止前首位递补、截止后不递补和候补退出顺序。

## M2结论

M2组局主闭环已完成：用户可以创建、发现、查看、报名、候补和退出球局；核心名额变化由服务端事务处理。组队和计分继续保持可选并默认关闭，留到后续里程碑实现。
