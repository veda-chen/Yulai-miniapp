# 羽来小程序 UI 升级设计方案 V1.0

## 1. 设计方向

### 1.1 产品气质

羽来是一款面向广州大学城羽毛球爱好者的组局工具。升级后的 UI 应该在「运动活力」与「干净可信」之间取得平衡：既要让球友感受到约球的轻快，也要让组织者对信息、状态和管理流程有掌控感。

### 1.2 设计关键词

- **清透**：充足的留白、柔和的层次、不堆砌信息。
- **节奏**：通过字号、色彩和间距建立清晰的信息主次。
- **可靠**：状态明确、反馈及时、操作可预期。
- **轻快**：羽毛球运动的灵动感通过圆角、色彩和微交互体现。

### 1.3 设计原则

1. **信息优先**：球局的时间、地点、名额、状态是用户最关心的问题，必须在首屏清晰呈现。
2. **状态可视**：报名、候补、截止、取消、变更等状态使用颜色 + 图标 + 文案三重表达。
3. **操作分层**：主操作使用实心主色按钮，次要操作使用描边或文字按钮，危险操作使用暖红色。
4. **一致性**：所有页面使用统一的色彩、间距、圆角和组件规范。

## 2. 色彩系统

### 2.1 主色调

保留羽来原有的绿色基因，但提升饱和度与明度，让品牌色更有辨识度。

| 名称 | 色值 | 用途 |
|------|------|------|
| 主色深绿 | `#0F5A4C` | 导航栏、主按钮、核心强调 |
| 主色翠绿 | `#1A9C7E` | 高亮文字、图标、进度条、选中态 |
| 主色浅绿 | `#E8F5F1` | 浅色背景、选中卡片、成功状态背景 |
| 主色淡绿 | `#F3FAF8` | 页面底层背景、悬浮卡片底色 |

### 2.2 功能色

| 名称 | 色值 | 用途 |
|------|------|------|
| 成功绿 | `#0D8A66` | 已报名、进行中、到场确认 |
| 警告琥珀 | `#D4940A` | 候补、待确认、变更提醒 |
| 错误珊瑚 | `#D9534F` | 取消、退出、删除、举报 |
| 信息蓝 | `#3B82F6` | 链接、提示、辅助说明 |
| 暖橙 | `#F97316` | 重要操作强调（如创建球局入口） |

### 2.3 中性色

| 名称 | 色值 | 用途 |
|------|------|------|
| 标题黑 | `#1A211F` | 主标题、重要文字 |
| 正文深灰 | `#3D4A46` | 正文、列表主文案 |
| 次要灰 | `#6B7B76` | 辅助说明、时间、地点 |
| 占位灰 | `#9DABA6` | 占位符、禁用态 |
| 边框灰 | `#DDE8E4` | 卡片边框、分割线 |
| 背景灰 | `#F2F7F5` | 页面背景（比当前略冷，更高级） |
| 纯白 | `#FFFFFF` | 卡片背景、浮层 |

### 2.4 色彩使用规则

- 页面背景使用 `#F2F7F5`，卡片使用 `#FFFFFF`。
- 关键文字使用 `#1A211F`，辅助文字使用 `#6B7B76`。
- 状态标签使用对应功能色的浅色背景 + 深色文字，不使用纯文字状态。
- 主按钮统一使用 `#0F5A4C` 渐变（`linear-gradient(135deg, #0F5A4C 0%, #1A9C7E 100%)`），增强质感。

## 3. 字体与排版

### 3.1 字体栈

微信小程序优先使用系统字体，保证渲染性能：

```css
font-family: -apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Helvetica Neue", sans-serif;
```

### 3.2 字号规范

| 层级 | 字号 | 行高 | 字重 | 用途 |
|------|------|------|------|------|
| H1 大标题 | 48rpx | 64rpx | 700 | 首页品牌标题 |
| H2 页面标题 | 40rpx | 56rpx | 700 | 球局标题、场馆名称 |
| H3 区块标题 | 32rpx | 44rpx | 600 | 卡片标题、区块标题 |
| 正文 | 30rpx | 44rpx | 400 | 主要文字内容 |
| 辅助文字 | 26rpx | 38rpx | 400 | 时间、地点、说明 |
| 标签文字 | 24rpx | 32rpx | 500 | 徽章、状态、提示 |
| 极小文字 | 22rpx | 30rpx | 400 | 时间戳、角标 |

### 3.3 字重规范

- 标题使用 600 / 700，正文使用 400。
- 同一页面内不超过 3 种字重，避免视觉混乱。

## 4. 间距与布局

### 4.1 基础栅格

以 8rpx 为基准单位：

```css
--space-1: 8rpx;
--space-2: 16rpx;
--space-3: 24rpx;
--space-4: 32rpx;
--space-5: 40rpx;
--space-6: 48rpx;
--space-8: 64rpx;
```

### 4.2 页面边距

- 页面水平边距统一为 `32rpx`（即 4 个基础单位）。
- 卡片内边距统一为 `32rpx`。
- 卡片之间间距统一为 `24rpx`。

### 4.3 圆角规范

| 名称 | 圆角 | 用途 |
|------|------|------|
| 小圆角 | 12rpx | 按钮、输入框、标签 |
| 中圆角 | 20rpx | 小卡片、列表项 |
| 大圆角 | 28rpx | 大卡片、首页 Hero、底部浮层 |
| 全圆角 | 999rpx | 胶囊按钮、徽章、头像 |

### 4.4 阴影规范

使用极浅的投影提升层级，避免过重阴影显得廉价：

```css
/* 卡片阴影 */
box-shadow: 0 4rpx 16rpx rgba(15, 90, 76, 0.06);

/* 悬浮按钮阴影 */
box-shadow: 0 8rpx 24rpx rgba(15, 90, 76, 0.18);

/* 强强调阴影 */
box-shadow: 0 12rpx 32rpx rgba(15, 90, 76, 0.12);
```

## 5. 图标系统

### 5.1 图标风格

- 使用 **2px 线性图标**，端点圆角，保持简洁一致。
- 图标颜色跟随文字层级：主色图标用于强调，灰色图标用于辅助。

### 5.2 基础图标集

每个页面应使用对应图标增强可读性：

| 场景 | 图标建议 |
|------|----------|
| 时间 | 时钟图标 |
| 地点 | 定位图标 |
| 人数 | 用户/人群图标 |
| 水平 | 奖章/星星图标 |
| 费用 | 人民币/钱包图标 |
| 联系方式 | 电话/微信图标 |
| 创建 | 加号图标 |
| 编辑 | 铅笔图标 |
| 分享 | 分享图标 |
| 报名成功 | 勾选圆形图标 |
| 候补 | 等待/时钟图标 |
| 取消 | 关闭/警告图标 |

### 5.3 实现建议

- 使用 `iconfont` 或 SVG 图标字体。
- 统一图标尺寸：`40rpx`（大）、`32rpx`（中）、`24rpx`（小）。

## 7. 页面级设计

### 7.1 首页

#### 现状问题
- Hero 区域仅有文字，视觉单调。
- 功能入口是简单的网格卡片，缺乏主次。
- 缺少「我的进行中的球局」快捷入口。

#### 升级方案

1. **顶部 Hero**
   - 使用深绿渐变背景（`#0F5A4C → #1A9C7E`）。
   - 左侧展示品牌名和日期问候语，右侧放置羽毛球/运动插画或几何图形装饰。
   - 增加「今日已报名球局」入口，若用户有进行中的球局则直接显示卡片。

2. **快捷操作区**
   - 突出「创建球局」为大尺寸主按钮，置于 Hero 下方。
   - 其余功能（找球局、看场馆、个人资料、消息）使用 icon + 文字的小卡片网格。

3. **我的球局模块**
   - 若用户已报名或组织了球局，首页中部展示「我的球局」横向滚动卡片。
   - 每张卡片显示：时间、场馆、状态徽章、进入详情入口。

### 7.2 球局列表

#### 现状问题
- 列表项信息平铺，缺少视觉层次。
- 时间、场馆、名额、状态没有明确的视觉分组。
- 缺少筛选入口的视觉暗示。

#### 升级方案

1. **顶部筛选栏**
   - 使用横向滚动的筛选标签（日期、场馆、水平、名额）。
   - 选中态使用主色浅绿背景 + 主色文字。

2. **球局卡片**
   - 卡片整体可点击，圆角 24rpx，带浅阴影。
   - 顶部一行：左侧开始时间（大号、主色强调），右侧状态徽章。
   - 中间：球局标题（加粗）、场馆名 + 定位图标。
   - 底部：水平要求徽章、已报名/上限人数、候补人数（如有）。
   - 若用户已报名，卡片边缘增加 4rpx 主色竖条或「已报名」角标。

3. **创建按钮**
   - 列表底部悬浮一个「+ 创建球局」胶囊按钮，主色渐变，带阴影。

### 7.3 球局详情

#### 现状问题
- 所有信息堆叠在卡片中，缺少信息分组。
- 状态提示使用大色块，视觉过重。
- 组织者操作按钮排列杂乱。
- 缺少视觉图标辅助。

#### 升级方案

1. **顶部信息卡**
   - 标题区：球局标题 + 仅链接可见徽章。
   - 核心信息行：时间、场馆、场号，每项配图标。
   - 名额进度：使用进度条或圆环展示已报名/上限。
   - 用户报名状态：使用独立的状态提示条（成功绿/警告琥珀）。

2. **操作区**
   - 主操作：报名/退出按钮使用主按钮样式，置于信息卡底部。
   - 次要操作：分享、编辑使用文字按钮或图标按钮横向排列。

3. **信息分组**
   - 活动说明、现场功能、参与名单分别使用独立卡片。
   - 参与名单使用头像 + 昵称的横向头像列表，提升社交感。

4. **变更提醒**
   - 当有重要变更时，使用顶部横幅（banner）展示，背景琥珀色，带「查看变更」按钮。

5. **组织者操作**
   - 使用底部固定操作栏：编辑、到场管理、开始/结束、取消分层展示。
   - 危险操作（取消）使用文字按钮或描边危险按钮，避免误触。

### 7.4 创建/编辑球局

#### 现状问题
- 表单字段全部平铺，缺乏分组。
- 开关与输入框混排。
- 缺少步骤感和视觉节奏。

#### 升级方案

1. **表单分组**
   - 使用分组标题：基本信息、时间设置、报名规则、联系方式、现场功能。
   - 每组之间增加 32rpx 间距。

2. **字段样式统一**
   - 所有输入框使用统一圆角和高度。
   - picker 右侧增加箭头图标提示可点击。

3. **开关区域**
   - 组队、计分开关使用独立卡片，配简短说明文字。

4. **底部操作**
   - 发布/保存按钮固定在底部，使用主按钮。
   - 编辑模式下增加「取消球局」危险文字按钮。

### 7.5 个人资料

#### 现状问题
- 页面过于简单，缺少用户头像展示。
- 字段缺少图标和说明。

#### 升级方案

1. **顶部个人信息区**
   - 展示微信头像（圆形，96rpx）。
   - 昵称大字号展示，学校/水平作为辅助信息。

2. **表单字段**
   - 每个字段左侧配图标（用户、学校、奖章）。
   - 使用卡片包裹表单，增加整体感。

3. **保存按钮**
   - 底部固定主按钮，提升操作确定性。

### 7.6 场馆列表与详情

#### 现状问题
- 场馆卡片信息较少。
- 详情页场地列表缺乏层次。

#### 升级方案

1. **场馆卡片**
   - 左侧使用首字母/场馆类型图标，右侧名称 + 地址。
   - 待核验场馆使用琥珀色徽章。

2. **场馆详情**
   - 顶部大图或色块占位（后续可放实拍图/平面图）。
   - 信息分层：地址、电话、开放时间、设施标签。
   - 场地列表使用编号 + 名称 + 位置说明的结构，增加可点击感。

### 7.7 报名管理

#### 升级方案

1. **成员卡片**
   - 展示头像 + 昵称 + 到场状态徽章。
   - 组织者点击可切换到场状态。

2. **候补名单**
   - 使用序号 + 昵称，补入按钮使用主色小号按钮。

### 7.8 消息列表

#### 升级方案

1. **消息卡片**
   - 未读消息左侧增加主色竖条。
   - 标题加粗，正文和时间分开展示。
   - 使用图标区分消息类型（报名、变更、取消、提醒）。

## 8. 动效与交互

### 8.1 转场

- 页面跳转使用微信默认转场即可，无需自定义复杂动画。
- 列表项点击增加 `opacity: 0.7` 的短暂按压反馈。

### 8.2 微交互

- 按钮点击：缩放 `scale(0.98)`，持续 100ms。
- 卡片按压：背景色微变 `#FAFCFB`。
- 状态变化：报名成功时使用 Toast + 按钮状态渐变。

### 8.3 加载状态

- 列表加载使用骨架屏（skeleton）优于纯文字「正在加载」。
- 提交操作使用按钮内置 loading 状态。

## 9. 实现建议

### 9.1 使用 CSS 变量管理主题

在 `app.wxss` 中定义全局变量：

```css
page {
  --primary: #0F5A4C;
  --primary-light: #1A9C7E;
  --primary-bg: #E8F5F1;
  --primary-surface: #F3FAF8;
  --success: #0D8A66;
  --warning: #D4940A;
  --danger: #D9534F;
  --info: #3B82F6;
  --text-title: #1A211F;
  --text-body: #3D4A46;
  --text-muted: #6B7B76;
  --text-placeholder: #9DABA6;
  --border: #DDE8E4;
  --surface: #FFFFFF;
  --page-bg: #F2F7F5;

  background: var(--page-bg);
  color: var(--text-body);
  font-family: -apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif;
}
```

### 9.2 更新导航栏配置

在 `app.json` 中更新导航栏颜色以匹配新主色：

```json
{
  "window": {
    "navigationBarTitleText": "羽来",
    "navigationBarBackgroundColor": "#0F5A4C",
    "navigationBarTextStyle": "white",
    "backgroundColor": "#F2F7F5"
  }
}
```

### 9.3 组件化建议

建议将以下 UI 元素提取为可复用组件：

- `yulai-button`：统一按钮样式和状态。
- `yulai-card`：统一卡片容器。
- `yulai-badge`：统一徽章。
- `yulai-empty`：统一空状态。
- `yulai-activity-card`：球局列表卡片。
- `yulai-member-row`：成员列表项。

### 9.4 图片资源建议

- 首页 Hero 可以使用羽毛球拍/羽毛球/场地的抽象插画，色调与主色一致。
- 场馆详情顶部可预留封面图区域，缺省使用场馆首字母 + 主色渐变背景。

## 10. 迁移清单

按以下顺序逐步替换现有 UI，避免一次性改动过大：

1. **基础样式**：更新 `app.wxss` 和 `app.json` 的颜色与字体。
2. **全局组件**：实现按钮、卡片、徽章、空状态组件。
3. **首页**：重设计 Hero 和功能入口。
4. **球局列表 + 详情**：替换卡片和详情页布局。
5. **表单页面**：统一输入框和表单分组。
6. **个人资料、场馆、消息、报名管理**：应用新组件规范。
7. **图标接入**：引入 iconfont，替换文字图标或纯文字说明。
8. **动效与细节**：添加按压反馈、加载骨架屏。

## 11. 设计前后对比

| 维度 | 当前设计 | 升级后设计 |
|------|----------|------------|
| 色彩 | 单一深绿 + 浅绿，层次弱 | 完整主色/功能色/中性色体系 |
