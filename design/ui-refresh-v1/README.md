# 羽来 UI 升级对比原型

这是独立浏览器原型，用同一组**示例数据**比较首页、球局详情、创建球局和工具箱的布局。左侧按仓库当前 WXML 页面结构复现，仅用于比较信息层级，**不是真机截图**；右侧是可点击的新方案。原型不连接云函数、不会报名或发布真实球局。

直接在浏览器打开 [index.html](index.html) 即可体验。左侧切换页面、320／375／430px 宽度、蓝／绿／橙品牌色、浅／深色、标准／大字，以及**实体／轻玻璃**控件材质。示例球场照片和羽仔素材引用仓库 `apps/miniprogram/assets/`，无需网络请求。

## 设计决定

| 页面 | 当前结构示意中的主要问题 | 新方案 |
| --- | --- | --- |
| 首页 | 问候、封面和卡片视觉重量接近，找球局在首屏较靠后 | 缩短封面，让“我的球局 → 找球局”相邻；卡片按名称与状态、时间、场馆、发起人与人数排序；搜索时明确展示新关键词状态 |
| 球局详情 | 时间、场馆、人数等量并列 | 名称、发起人和状态集中在顶部，时间成为主信息，报名人数与余量同组；底部只突出当前报名动作 |
| 创建球局 | 长表单一次展示许多低频字段 | 先填名称、场馆、时间、人数；费用、联系和现场设置折叠；发布前查看摘要与字段级错误 |
| 工具箱 | 各工具使用同等重量的列表行 | 用短说明和统一入口快速选工具；示例草稿提供“继续上次”；公平组队显示三阶段，计分提供清楚的撤销 |

首页与创建页保留球场照片，首页封面使用羽仔。球局卡片保持实体表面，半透明材质不用于承载正文。轻玻璃只用于顶部导航、悬浮底部导航和报名／发布固定操作区：浅色与深色分别使用适当的半透明底色、模糊、细边框和轻阴影，主要按钮仍为不透明品牌色。浏览器不支持背景模糊时自动使用实体背景。左侧“实体”可随时对比；这只是原型材质开关，不会改写现有小程序个性化配置。品牌色只用于关键操作及选中状态；成功、候补和危险状态继续使用固定语义色。主要点击区域以 44px 逻辑尺寸为目标，页面内容可纵向滚动，卡片及控件不得在 320px 下横向溢出。

原型交互包括搜索防抖与空结果、进入详情和演示报名反馈、表单本机演示草稿与必填校验、更多设置、发布前确认、8 人赛程预览与确认、临时计分与撤销。示例赛程由仓库现有公平编排算法产生：8 场、每人 4 场；页面只是展示固定示例，不重新实现业务算法。场馆、个人中心、完整列表和其他工具入口在原型中仅作入口示意。

## 小程序组件改造清单

1. **基础规范**：在现有外观系统中统一文字层级、间距、边框、圆角、控件最小高度以及蓝绿橙与明暗模式；保留语义状态色和减少动效设置。
2. **首页**：调整 `pages/index/index` 的问候与封面高度；扩展 `hero-banner` 和 `activity-card` 的展示层；“我的球局 → 找球局”顺序及横滑行为保持不变；复用当前搜索和状态逻辑。
3. **详情**：调整 `pages/activities/detail` 的顶部信息层级、时间、容量和报名固定栏；组织者操作与危险操作仍按现有权限与确认流程执行。
4. **创建**：调整 `pages/activities/form` 的字段分组，更多设置用可展开区域；保留现有字段验证、草稿、场馆选择与发布流程；发布前摘要只读取当前表单数据。
5. **工具**：更新 `pages/tools/index` 与 `tool-card`；继续入口的真实实现需先确认本机草稿是否存在并未过期。`pages/tools/rotation` 与 `pages/tools/scoring` 只调整展示，继续调用原有编排与计分逻辑。
6. **共享控件**：优先扩展 `ui-button`、`section-header`、`status-chip`、`ui-icon`、`empty-state`、`score-board`，不另造业务状态或复制云端请求。
7. **玻璃材质验证**：小程序端需在微信开发者工具及 Android／iOS 真机分别验证背景模糊支持、滚动性能、底部安全区和大字对比度；不支持时使用实体表面，不让正文透到卡片下方。
8. **分批迁移与验收**：先迁移首页与球局卡片，再迁移详情和创建，最后迁移工具；每批检查 320／375／430px、三配色、深浅主题、大字、键盘与安全区，并做 Android／iOS 真机验收。

浏览器原型仍用于四页完整布局对比。实际小程序已先迁移轻玻璃底部导航、详情报名栏和创建保存栏；其他布局与交互仍以原型为设计参考。云数据库、接口、报名权限与公平编排算法未改变。
